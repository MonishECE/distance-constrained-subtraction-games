## Theorem D statement and justification

For every integer 170 <= k <= 213 and every heap size n >= 0, the unrestricted starting position in D(k,1) is losing exactly when

`n mod (2k+216) in {0,214,k+215}`.

The least positive starting-position period is `2k+216` for 170 <= k <= 212, and is 214 for k=213. At the latter endpoint the displayed modulus is 642 and its residues are {0,214,428}; these express precisely the multiples of 214.

The induction mechanism is valid: if k successive full P/N rows agree at offsets t and t+p, the next rows agree because each depends on the preceding k rows. For n >= t+k both recurrences allow every removal size 1..k. This proves full-row repetition from t. Starting outcomes consequently repeat from t+k. Verifying the proposed starting formula through the inclusive endpoint t+k+p-1 covers the earlier prefix plus a complete period. It therefore proves the formula for every n, rather than extrapolating a numerical streak.

D's t values are 444 at k=170; 339,341,341,342,339,342 at k=171..176; and 0 at k=177..213. The bridge reaches n=1169 at k=170. A starting formula periodic from n=0 does not imply that the full P/N rows repeat from n=0.

The minimality argument is independent of the game solver: a nonzero translation preserving a three-element residue set must have order three. The residues must therefore be equally spaced. For {0,A,k+A+1} modulo 2k+A+2 this happens exactly at k=A-1. For A=214 this is k=213.

## Confirmed defects and required changes

1. **The combined verifier skips D.** `src/verify_package.py`, command list at lines 22–26, invokes A/B and C but never `src/verify_theorem_d.py`. Its comparison loop only checks files generated by those commands. All D artifacts could consequently be changed without that command validating them. Add D to the command list, compare its regenerated CSVs and summary, and check its theorem table when the manuscript section is added.

2. **Optimization can produce false PASS labels.** D's decisive checks at `src/verify_theorem_d.py` lines 41–58 and 70–73 are Python assertions. Running Python with `-O` or `PYTHONOPTIMIZE` removes them. In a controlled local test, I replaced all three solvers with an invalid all-zero/all-N implementation and ran `certify(170)` under `python -O`: it returned both crosschecks as PASS and status `PROVED: fixed-k certificate`, despite failing the actual formula. This does not refute the legitimate certificate; it demonstrates an unsafe verification mode. Reject optimized execution with an ordinary `if not __debug__: raise RuntimeError(...)`, or use explicit conditional exceptions for the checks. Place the guard where imports and direct `certify` calls also encounter it. The `assert __debug__` guards in the A/B and combined verifiers are themselves removed under optimization, so they are ineffective protection too. C has the same assertion dependency.

3. **The advertised combined verifier fails on Linux with committed JSON bytes.** The committed `data/certificates/theorem_B_audit.json` has CRLF line endings, confirmed directly from its GitHub blob. Regeneration on Linux produces LF. `verify_package.py` compares raw bytes at line 31, so it raises `nonreproducible certificate`. `.gitattributes` explicitly uses `* -text`, preserving the mismatch in checkouts. Restore a consistent JSON byte convention in the repository, or compare parsed JSON while retaining deliberate byte/hash checks for the CSV evidence. In the local review copy, normalizing certificate JSON files to LF allowed the whole existing combined suite to pass. That local diagnostic normalization was not pushed.

4. **D is not integrated into the paper or reproducibility instructions.** PR #3 adds four files: the script, two CSVs, and a summary. It adds no theorem statement, proof section, manuscript table, README result, or reproducibility command. This is appropriate as a candidate artifact, but should be completed before presenting D as a published theorem in the manuscript. Include the exact parameter restriction and k=213 collapse; avoid calling 642 the least period there.

## False-positive and false-negative searches

A separate C++ implementation evaluated legal moves and the losing-state predicate directly, without constructing Theorem A's interval endpoints. It agreed row-for-row and start-for-start with the interval solver for all 77 B/C/D cases through `N=12p+2k`, with N ranging from 1764 to 8130. Every certified residue formula had zero mismatches. The certificate windows themselves also matched, and subsequent rows repeated across the tested ranges. The induction argument, not the finite length of this extra scan, supplies the all-n conclusion.

For A, the independent solver checked k=1..20, every m=0..2k+1, and n=0..150: 460 parameter pairs. This includes k=1, m=0, and m>=k-1 where previous-removal constraints can forbid every subsequent move. The interval intersection proof and finite-memory argument are valid generally; these tests are extra checks, not a substitute for those proofs.

## Affine catalogs

Regenerated the entire affine batch for k=58..78 with direct SG crosschecks. All eight CSV tables matched the committed logical records; the analysis text matched after trimming trailing whitespace. All first-period covers consisting of selected segments **plus residual points** had zero extra cells and zero missing cells.

The cross-parameter tracks alone had zero extra cells but **1467 missing P-state cells**, summed over the 21 diagrams. The per-k misses for k=58..78 are:

`97,94,87,85,85,86,83,81,78,79,73,71,71,69,63,61,52,43,39,37,33`.

This incompleteness is already reported by `results/affine/track_only_validation.csv`. It is a limitation rather than a false theorem in the current paper. Do not describe those tracks as a complete symbolic P-state classification. First-period covers also require care across transients: B's full-state repetition starts later than n=0 for k=58..64.

## Supporting scan limits

Checked all 224 records with a reported period in the four `*scan_results.csv` files against independent P/N outcomes. Each was checked through at least n=5000, or through the reported preperiod plus eight reported periods plus 2k when larger. The maximum checked n was 11174. No residue mismatch appeared in those ranges.

An exact k-row P/N repetition witness at the **reported starting period** was found for 163 records. It was not found for the other 61 records within these bounds. This is not a counterexample: the full-state sequence can have a different period from the starting sequence (k=53 provides a known example), or a longer transient. Those 61 records were not certified by this particular test.

The original 200000/500000-heap scans were not regenerated in full. Their maximum SG values and fingerprints were not independently revalidated. The merged `m1_deep_35_120.csv` is not separately rerun by this audit. Numerical scan consistency must not be promoted to a new all-n theorem without an appropriate certificate and bridge.
